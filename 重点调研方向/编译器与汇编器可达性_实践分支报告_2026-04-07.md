## 4. 实测结果摘要

### 4.1 L0（.insn）路径：可达

在当前 WSL2 GNU 工具链下，L0 10 条样例均可编译并反汇编。

反汇编得到的 10 条指令字如下：

| 指令 | 指令字 |
| --- | --- |
| PSADD.B | `0x94c5853b` |
| PSSUB.B | `0xd4c5853b` |
| PSSHAR.HS | `0xf8c5a51b` |
| PSSHLR.HS | `0xb8c5a51b` |
| PMULQ.H | `0xd0c5f53b` |
| PMULQR.H | `0xd4c5f53b` |
| PM2ADD.H | `0x80c5d53b` |
| PM2ADDA.H | `0x88c5d53b` |
| PM4ADD.B | `0x84c5d53b` |
| PM4ADDA.B | `0x8cc5d53b` |

结论：L0 已满足“编码可达、可重复编译反汇编”的阶段目标。

### 4.2 L1（助记符）路径：不可达

L1 10 条样例在当前 GNU 工具链下全部失败（0/10）。

统一报错形态：

- `Error: unrecognized opcode ...`

补充诊断（GNU 尝试显式启用 P 扩展标记）：

- `Error: cannot find default versions of the ISA extension 'p'`

结论：当前失败不是样例语法拼写偶发错误，而是“工具链前端不具备 P 助记符识别能力”。

证据文件：

- `../实践尝试/P扩展深入落地尝试/工具链与语义最小闭环_子任务实践方案/reports/smoke-l1-wsl2-20260407.md`

---

## 5. 根因分析（可追溯）

### 5.1 主根因：工具链能力边界

- 当前 WSL2 仅有 GNU riscv64 工具链；该版本口径下不支持本批 P 助记符。
- `-march=rv64gc` 不包含 P；即使尝试 `-march=rv64gcp`，仍提示找不到 P 扩展默认版本。

### 5.2 次根因：L1 目标路径与现网工具不匹配

- L1 的推荐路径是 LLVM experimental-p。
- 但当前 WSL2 环境中 Clang/LLVM 未安装，导致无法执行该分支验证。

### 5.3 影响范围

- 影响的是“助记符可达性（L1）”，不影响 L0 `.insn` 主闭环。
- 语义模型、样例生成、expected 生成链路均已可用。

---

## 6. 阶段结论

1. 当前阶段“编译器与汇编器可达性”已形成明确分层结论：
   - L0：已打通
   - L1：当前工具链不可达
2. 项目可继续沿 L0 主路径推进语义闭环与对拍验证，不应因 L1 阻塞停工。
3. L1 应作为“工具链升级后的复测分支”，而非当前里程碑阻断项。

---

## 7. 下一步建议（按优先级）

1. 继续主线：基于 L0 + 语义模型推进 actual 导出与 diff 对拍（T5/T6）。
2. 固化证据：每次工具链升级后复跑 `wsl_l1_smoke.sh` 并追加报告。
3. 条件允许时，补充 LLVM experimental-p 环境，单独验证 L1 可达性分支。
