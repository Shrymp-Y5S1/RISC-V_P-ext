# 高价值指令子集语义闭环调研（基于 P-ext-proposal v0.20-draft）

## 0. 证据分级与回炉原则

为避免把草案文本中的潜在笔误写成“强结论”，本轮采用三层证据分级：

1. A 级（可直接定论）
- 来自 P-ext-proposal.html 的指令语义描述与伪代码。

2. B 级（交叉补证）
- 来自外部公开资料的同版本语义文本（如 John Hauser 的 RVP-baseInstrs-Sail-020.txt）。
- 作用是交叉校核，不替代 A 级。

3. C 级（实现侧可达性）
- 来自工具链文档（如 LLVM experimental-p 状态）用于判断“能否尽快验证”，不作为 ISA 语义最终裁决。

本文件中：
- “可定论”只写 A 级已闭环结论。
- “待补证”专门承载 A/B 存在差异或文字不稳定项。

## 1. 调研目标

本文件聚焦“高价值指令子集语义闭环”，目标不是罗列指令，而是回答 4 个工程问题：

1. 语义是否可形式化：能否写成统一的数学/位级规则。
2. 边界是否可验证：溢出、饱和、舍入、跨 lane 归约是否可用测试覆盖。
3. 跨 XLEN 是否一致：RV32 双寄存器对形式能否和 RV64 单寄存器语义对齐。
4. 实现是否可落地：优先子集是否能尽快形成“性能 + 正确性”证据。

## 3. 子集 A：饱和加减（PSADD/PSADDU/PSSUB/PSSUBU）

## 3.1 统一语义模板

设元素宽度为 w（w in {8,16,32}）：

- 有符号饱和加：r = clamp(a + b, -2^(w-1), 2^(w-1)-1)
- 无符号饱和加：r = clamp(a + b, 0, 2^w-1)
- 有符号饱和减：r = clamp(a - b, -2^(w-1), 2^(w-1)-1)
- 无符号饱和减：r = max(a - b, 0)

其中 a,b,r 都按 lane 独立计算。

## 3.2 原文语义证据（摘录要点）

- PSADD.B 明确是 signed saturating addition，范围 [-128,127]。
- PSADDU.B 明确是 unsigned saturating addition，范围 [0,255]。
- PSSUB.B 明确是 signed saturating subtraction，范围 [-(2^7),2^7-1]。
- PSSUBU.B 明确是 unsigned saturating subtraction，负值截断为 0。

## 3.3 闭环关注点

1. lane 级独立性：不同 lane 不相互进位影响。
2. 宽度一致性：B/H/W 三种宽度只应体现阈值差异，不应改语义本质。
3. 跨 XLEN：RV64 的 .W 是 packed word；RV32 通过 .D* 双寄存器对承载双宽。

## 3.4 高优先级边界用例

- signed add：max + 1、min - 1、max + max、min + min。
- unsigned add：all-ones + 1、all-ones + all-ones。
- signed sub：max - (-1)、min - 1、0 - min。
- unsigned sub：0 - 1、small - big。

## 4. 子集 B：饱和/舍入移位（PSSHA/PSSHAR/PSSHL/PSSHLR/PSSLAI）

## 4.1 统一语义结构

这组指令核心是“带符号 shift amount 的双分支语义”：

- 若 sshamt < 0：执行右移（算术或逻辑，取决于指令），部分指令带舍入。
- 若 sshamt >= 0：执行左移并做饱和截断（signed 或 unsigned 饱和，取决于指令）。

## 4.2 规范可直接定论（A 级）

1. PSSHA.HS
- rs2[7:0] 作为有符号 shift amount。
- 负数右移（算术右移），正数左移并做 signed 饱和。
- 任一 lane 饱和时置位 vxsat。

2. PSSHAR.HS
- 与 PSSHA.HS 类似，但右移分支带 rounding。
- 伪代码采用“扩一位后 +1 再取高位”策略表达舍入。

3. PSSHL.HS / PSSHLR.HS
- 右移分支是逻辑右移；左移分支做 unsigned 饱和（上限 0xFFFF for .HS）。
- PSSHLR 在右移路径带 rounding。

4. PSSLAI.H
- 立即数左移，signed 饱和，vxsat 按 lane 聚合。

## 4.3 外部补证（B 级）

联网补证到 RVP-baseInstrs-Sail-020.txt 后，以下点与 A 级结论一致：

1. PSSHL.HS 左移路径采用 unsigned 饱和（超上限置 0xFFFF 并置位 vxsat）。
2. PSSHLR.HS 右移路径采用“(x @ 0b0) >> n 后 +1 再截位”的位级舍入实现。
3. RV32/RV64 的 SSHL/SSHLR 语义骨架与 .HS/.WS 族保持同构。

但该外部文本也明确声明“代码未测试，可能包含错误”，因此仅作为交叉证据，不替代主规范。

## 4.4 待补证与降级项

1. 舍入术语命名
- 当前可稳定落地的是位级实现公式；“ties-up / away-from-zero”等术语名称建议在官方 Sail 模型或任务组决议中最终锁定。

2. shift amount 极值
- sshamt <= -w、sshamt >= w 的行为在多处可读到，但个别文本表述存在记号不统一风险，建议以回归样例锁死。

3. vxsat 语义
- 该组多处明确“任一 lane 饱和则置位”，应做 sticky 行为验证。

4. 草案文本稳定性
- 个别伪代码段存在变量名/常量写法不稳，建议以“指令族一致性 + 对照样例 + 外部实现”三重锁定。

## 4.5 高优先级边界用例

- sshamt = {-w-1, -w, -1, 0, 1, w-1, w, w+1}
- lane = {min, min+1, -1, 0, 1, max-1, max}
- rounding 专项：刚好半位、半位附近正负样本。

## 5. 子集 C：Q-format 乘法与乘加

## 5.1 PMULQ/PMULQR 语义主线

1. PMULQ（不带 R）
- 本质是 Q-format 乘法后取高位。
- 对 16-bit 情况，等价提取 (a*b)[30:15]（Q15 对齐）。
- 特殊溢出点：a == min 且 b == min 时饱和到 max，并置 vxsat。

2. PMULQR（带 R）
- 在提取前加 rounding 常量。
- 16-bit 情况常量为 2^14；32-bit 情况常量为 2^30。

3. MULQ/MULQR（标量 XLEN）
- 对全 XLEN 数据执行同类 Q-format 规则。
- RV32 与 RV64 分别使用各自极值与位段提取规则。

## 5.2 MQACC/MQRACC 语义主线

- MQACC.H00/H01/H11：选取半字组合乘法，提取 [46:15] 后累加到 rd。
- MQRACC.*：在提取前加 2^14 做 rounding，再提取 [46:15] 并累加。
- 这类指令是“读写 rd”的累加形式，必须考虑累加链溢出与回绕行为。

## 5.3 PMQ2ADD/PMQR2ADD 语义主线

- 每个 32-bit 结果 lane 来自 2 个半字乘积项的横向求和。
- PMQR2* 在每个乘积项提取前都加 2^14，再做位段提取后求和。
- PMQ2ADDA/PMQR2ADDA 是读写 rd 的累加版。

## 5.4 外部补证（B 级）

从 RVP-baseInstrs-Sail-020.txt 可直接读到并与 A 级互证的关键位级细节：

1. PMULQR.H 使用 +2^14 后取 [30:15]。
2. RV64 MQRACC.W00/W01/W11 使用 +2^30 后取 [94:31]。
3. PMQ2ADD.H/PMQR2ADD.H 采用“每个半字乘积先位段提取，再二项横向求和”的结构。

这使 Q-format 族的“舍入常量与位段选择”具备跨资料的一致性证据。

## 5.5 与命名约定章节的关联

#_packed_simd_instructions_with_horizontal_additionsubtraction 明确指出：

- 2ADD/4ADD 是横向归约语义，不是普通逐 lane 一一运算。
- Q-format 乘法不是 widening 乘法，产品会先按 Q-format 下移，这也是 PMQR2ADDA.H 等指令“有 headroom”的原因之一。

## 5.6 高优先级边界用例

- Q 乘法极值：(-1.0)×(-1.0) 对应的 min*min 饱和点。
- rounding 切换点：乘积低位刚好在半位阈值上下。
- 累加链：长序列 MAC 下的误差累计与回绕行为。

## 6. 子集 D：PM2/PM4 横向乘加

## 6.1 PM2（两项横向）

- PM2ADD.H：每个 32-bit lane = low*low + high*high。
- PM2ADDA.H：在 PM2ADD 基础上累加到 rd。
- PM2ADD.HX：交叉乘 low*high + high*low。
- SU/U 变体分别覆盖 signed×unsigned、unsigned×unsigned。

## 6.2 PM4（四项横向）

- PM4ADD.B：每个 32-bit lane 汇总 4 组 byte 乘积之和。
- PM4ADDA.B 及 ASU/AU 变体：在符号组合变化基础上提供累加版本。

## 6.3 闭环关注点

1. 横向归约导致位宽增长
- 需验证“每组乘积位宽 + 归约和位宽”是否与实现位宽匹配。

2. 累加版读写 rd
- 与流水线旁路、写后读相关风险最高，需单列验证。

3. 符号组合
- S/S、S/U、U/U 三类混合是错误高发点。

## 7. RV32 双寄存器对闭环要求

原文证据：
- #_rv32_double_register_equivalences
- #_double_wide_three_register_forms
- 代表指令：#_psadd_db_rv32, #_pssha_dhs_rv32

关键规则：

1. .D* 形式通常等价为“even 寄存器执行一次 + odd 寄存器执行一次”。
2. rd/rs1/rs2 需为偶寄存器编号（x0 允许），并遵守 rd+/rs1+/rs2+ 语义。
3. 语义验证应同时覆盖：
- 单寄存器形式
- 双寄存器等价展开形式
- 二者逐 lane 对比一致性
4. 三寄存器双宽形式还需验证“执行顺序不破坏 rs2”约束：
- 原文明确要求两条等价单宽展开要么并行，要么采用不会覆盖 scalar rs2 的次序。
- 这是 RV32 映射到微架构实现时最容易忽略的行为约束。

## 8. 语义闭环交付模板（建议直接按此推进）

## 8.1 每条代表指令最小语义卡片

1. 输入/输出 lane 定义。
2. 数学表达式。
3. 饱和阈值与舍入规则。
4. vxsat 是否置位。
5. RV32 双寄存器等价展开式。

## 8.2 用例矩阵（必须覆盖）

1. 数据边界：min/max/0/±1。
2. shift 边界：{-w, -1, 0, 1, w-1, w}。
3. 乘法边界：min*min、min*max、max*max。
4. 累加链：短链（2~4 次）+ 长链（>32 次）。
5. RV32 对齐：单条 .D* 与两条单宽展开结果一致。

## 8.3 验证判定准则

- 位级结果完全一致。
- 饱和点触发一致。
- rounding 临界点一致。
- vxsat 置位行为一致。

## 8.4 外部补证用例（建议新增）

1. 主规范与 Sail 对照
- 对 PSSHL/PSSHLR、PMULQR、PMQR2ADD 各抽 20 组随机样本，要求二者结果一致。

2. RV32 双宽展开一致性
- 将 .D* 指令与“两条单宽展开”做等价比对，额外覆盖 rs2 与 rd/rd+ 寄存器重叠场景。

3. vxsat 聚合一致性
- 对“单 lane 饱和、多 lane 饱和、无饱和”三类模式分别做回归，确认置位行为稳定。

## 9. 建议的第一阶段执行顺序（两周可落地）

1. Week 1：先完成 PSADD/PSADDU/PSSUB/PSSUBU + PSSLAI/PSSHAR 的语义卡片与边界用例。
2. Week 2：完成 PMULQ/PMULQR + PMQ2ADD + PM2ADD/PM4ADD 的对照测试与差异清单。

阶段目标：先拿到“语义正确性证据包”，再进入性能评估与微架构映射。
