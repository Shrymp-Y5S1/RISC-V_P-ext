## 1. 目标与完成定义（DoD）

### 1.1 本轮目标
在 2~3 周内完成“能编译、能运行、能对拍、能复现”的最小闭环，不追求大而全覆盖。

### 1.2 非目标（本轮不做）
- 不做完整 P 扩展全指令实现。
- 不做完整 ACT4 认证流程集成。
- 不做编译器自动选指（pattern matching）优化。

### 1.3 完成定义（必须同时满足）
1. 同一批 case 可重复编译并产出一致反汇编结果。
2. 最小指令子集至少 10 条指令完成“黄金模型 vs 实际执行”对拍。
3. 输出至少 1 份可追溯表：`input -> expected -> actual -> vxsat -> pass/fail`。
4. 随机测试使用固定 seed，重复运行结果一致。
5. 形成版本锁定页（规范版本、工具链版本、关键仓库 commit、运行命令）。

### 2.1 联网确认（2026-04-05）
1. `riscv-p-spec` 仍为 working draft，版本演进可能影响语法与语义细节。
2. LLVM 文档明确存在 `experimental-p`，并要求实验扩展流程（`-menable-experimental-extensions`）。

4. `riscv-arch-test` ACT4 定位为认证测试，不替代完整验证。
5. NMSIS-DSP 可用于通信算子基线，但不作为本轮最小闭环必需项。

## 3. 最小闭环技术路线（双路径）

### 3.1 路径 A（必做）：L0 `.insn` 编码可达
目标：无论助记符是否可用，先确保编码、反汇编、运行路径可达。

### 3.2 路径 B（建议做）：L1 助记符可达
目标：验证当前工具链对目标助记符的真实支持情况，减少后续人工编码成本。

### 3.3 为什么必须双路径
- 路径 A 解决“今天就能干起来”的确定性问题。
- 路径 B 解决“后续可维护性与可读性”的工程问题。
- 两者并行可显著降低草案演进带来的返工风险。

## 6. 输入集与对拍口径（强约束）

### 6.1 边界输入
1. 8-bit 有符号：`[-128, -127, -1, 0, 1, 126, 127]`
2. 16-bit 有符号：`[-32768, -32767, -1, 0, 1, 32766, 32767]`
3. 累加初值（用于 `*ADDA*`）：`[-2147483648, -1, 0, 1, 2147483647]`

### 6.2 shift 专项（`rs2[7:0]` 解释为有符号）
使用 `sshamt` 集合：`[-17, -16, -15, -1, 0, 1, 15, 16, 17]`

### 6.3 随机输入
- 固定 seeds：`[1, 7, 42, 20260405]`
- 每条指令每个 seed 生成 200 组样例。

### 6.4 对拍字段（统一 CSV）
`case_id, instr, rs1, rs2, rd_in, expected_rd, expected_vxsat, actual_rd, actual_vxsat, pass`

## 8. 每个子任务的执行要点

### T0：版本锁定
`version-lock.md` 至少包含：
1. `riscv-p-spec` 文档来源与拉取日期。
2. 工具链版本（gcc/binutils/clang/objdump）。
3. 运行环境（Windows + WSL/容器信息）。
4. 关键命令与参数快照。

### T1：L0 `.insn` 路径（必做）
建议命令模板：
```bash
riscv64-linux-gnu-gcc -c asm_l0/psadd_b_insn.S -march=rv64gc -mabi=lp64d -o build/psadd_b_insn.o
riscv64-linux-gnu-objdump -d build/psadd_b_insn.o > build/psadd_b_insn.objdump
```
若在 WSL2 中执行，可直接使用：
```bash
bash scripts/wsl_l0_smoke.sh
```
验收：
1. 编译通过。
2. 反汇编可定位目标编码。
3. 结果可重复。

### T2：L1 助记符路径（建议）
建议命令模板：
```bash
clang --target=riscv32-unknown-elf -menable-experimental-extensions \
  -march=<本地可用P版本串> -mabi=ilp32 \
  -c asm_l1/psadd_b_mnemonic.S -o build/psadd_b_mnemonic.o
```
验收：
1. 对每条助记符记录 `成功/失败`。
2. 失败必须记录报错信息与替代方案（退回 `.insn`）。

### T3：黄金语义模型
最小函数集合建议：
1. `sat_signed(x, w)`
2. `sat_unsigned(x, w)`
3. `psadd_b/pssub_b`
4. `psshar_hs/psshlr_hs`
5. `pmulq_h/pmulqr_h`
6. `pm2add_h/pm2adda_h`
7. `pm4add_b/pm4adda_b`

验收：
- 每个函数附带至少 5 个边界样例单测。

### T4：样例与期望值生成
流程：
1. `gen_cases.py` 生成 `cases/*.json`
2. `model_eval.py` 生成 `expected/*.json`

验收：
- 相同 seed 多次运行生成文件一致（可对比哈希）。

### T5：执行与差分
流程：
1. 运行目标执行环境（优先支持 P 的 ISS/QEMU/Sail 方案）。
2. 导出 `actual/*.json`。
3. `diff.py` 输出 `reports/diff-*.csv`。

验收：
- 至少输出 1 份完整差分表与 1 份失败样例清单。

### T6：失败归因
归因标签固定为：
1. `MODEL_BUG`
2. `IMPLEMENTATION_BUG`
3. `CONFIG_MISMATCH`

验收：
- 每个失败 case 必须归到上述三类之一。

## 10. 风险与回退策略

1. 风险：助记符不可用。
- 回退：全部切到 `.insn`，保证路径 A 先闭环。

2. 风险：执行环境不支持当前草案语义。
- 回退：先完成“编码/反汇编/黄金模型”闭环，执行对拍延后一周并记录阻塞点。

3. 风险：`vxsat` 不易直接观测。
- 回退：先用“结果是否命中饱和值 + 模型标记”验证，再补 CSR 读取路径。

4. 风险：RV32 双寄存器与 RV64 语义混淆。
- 回退：本轮先固定 RV32/Halfword/Byte 子集，暂不扩展 RV64 Word 变体。
